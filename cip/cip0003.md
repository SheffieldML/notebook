# CIP-0003: Execute GPy tutorials in CI

## Summary

Run `GPy/*.ipynb` automatically against a **pinned GPy version** so the
tutorials cannot silently return to Python 2 / broken Plotly. The first green
run is a gate for **GPy 1.15.0**: do not treat those tutorials as compatible
with 1.15 until this job (or an equivalent local runner) is green after
CIP-0001 and CIP-0002.

## Motivation

There is no CI in this repository. The GPy tutorials last targeted a Python 2
kernel. A one-off execute against GPy 1.15.0 (2026-10-24) found 16 failures;
without a job, the next GPy or Plotly bump will rot the same files again.

GPy's own pytest suite does not check out this repository, so library-green
does not mean tutorial-green.

## Detailed Description

### First green run (GPy 1.15.0)

Hold the claim “tutorials work on GPy 1.15” until:

1. CIP-0001 is Implemented (Python 3 / NumPy 2 / matplotlib / config).
2. CIP-0002 is Implemented (no Chart Studio in tutorial cells).
3. This CIP's runner executes all `GPy/*.ipynb`:
   - required notebooks pass;
   - `SVI.ipynb` and `optimizer-implementation.ipynb` pass if `climin` is
     installed in the job, otherwise **skip** with a documented optional extra;
   - `index.ipynb` has no required code;
   - `config.ipynb` does not raise (markdown-only after CIP-0001).

The GPy GitHub Release / PyPI upload for 1.15.0 is GPy's decision; this CIP
only defines when **this repo** can say the tutorials match that release.
Coordinate with SheffieldML/GPy#1235 so they do not announce working tutorials
ahead of a green run.

### Runner design

- **Command:** `nbclient` or `jupyter execute`, `MPLBACKEND=Agg`, per-notebook
  timeout, kernel from the job env.
- **GPy pin:** install GPy from a version or git SHA recorded in the workflow
  (`gpy==1.15.0` once published; until then the `release/1.15.0` branch or
  #1235 SHA). Do not float on GPy `devel` for the release-gate run.
- **Python:** one version GPy 1.15 supports and Actions provides (3.12).
- **Extras:** `gpy[plotting]` plus Jupyter (`nbclient`, `ipykernel`), `pods`,
  and `climin` so SVI/optimizer notebooks are required. East Timor in
  `GPyCrashCourse` is loaded from `lawrennd/datasets_mirror` until
  `pods.datasets.east_timor` is on PyPI. A second Actions job installs current
  PyPI GPy; it is informational (`continue-on-error`) and is not the 1.15
  release gate.
- **Where:** GitHub Actions **in this repository** (the files under test live
  here). GPy may later add a complementary job that checks out a **pinned SHA
  of this repo**; that is GPy's CIP, not this one.
- **Non-goals:** `lab_classes/`, `compbio/`, `GPy-phil/`.

### After the first green run

Keep the job on the default branch. Failures block merges that touch `GPy/`.
Other directories stay unexecuted until a later CIP.

## Implementation Plan

1. Script (e.g. `scripts/run_gpy_tutorials.sh`) that executes `GPy/*.ipynb`
   with skip rules for climin.
2. GitHub Actions workflow: Python 3.12, install pinned GPy + extras, run the
   script, upload executed notebooks on failure.
3. Record the GPy pin and climin skip policy in the workflow comments.
4. First green run against the 1.15.0 candidate; comment on GPy#1235.
5. Point README GPy tutorial section at the workflow badge.

## Backward Compatibility

No notebook pedagogy change beyond CIP-0001/0002. Contributors gain a required
check when they edit `GPy/` tutorials.

## Testing Strategy

- Reproduce the 2026-10-24 inventory locally, then CI.
- Job fails if a required notebook raises.
- Job does not use Plotly Cloud credentials (CIP-0002).
