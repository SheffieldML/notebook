# CIP-0001: Port GPy tutorials to current Python

## Summary

Update the **GPy tutorial notebooks** in `GPy/*.ipynb` so their source cells
are valid Python 3 and NumPy 2. This CIP is cell content only: `print` /
`xrange` / kernelspec, NumPy scalar formatting, matplotlib `errorbar` format
strings, and `config.ipynb` INI pasted as code. Plotly library choice is
CIP-0002. Execution CI is CIP-0003.

## Motivation

On 2026-10-24 the GPy tutorials were executed against **GPy 1.15.0**
(`nbclient`, `MPLBACKEND=Agg`). 2 of 18 code notebooks passed
(`ParametricNonParametricInference`, `Space_time_effects`). Most of the rest
fail on **Python 2 syntax** that this repository still ships (`print x`,
`xrange`, `kernelspec: python2`). Readers following GPy's tutorial links hit
those errors on any current GPy, independently of the library's own test suite.

GPy 1.15.0 is intended as the last release that still declares Python 3.9/3.10.
Shipping it while the public tutorials are Python 2 is a documentation failure.

## Detailed Description

### Scope

In: `GPy/*.ipynb` (the tutorial set linked from GPy docs and this repo's
README).

Out: `lab_classes/`, `compbio/`, `GPy-phil/`, `theano_day/`. Those trees are
the same vintage; they are not this CIP.

### Failure inventory (2026-10-24)

**Python 2 `print` / `xrange`:**

- `GPyCrashCourse.ipynb`
- `basic_classification.ipynb`
- `basic_kernels.ipynb`
- `coregionalized_regression_tutorial.ipynb`
- `models_basic.ipynb`
- `multiple outputs.ipynb`
- `sparse_gp_regression.ipynb`
- `sampling_hmc.ipynb` (`xrange` as well as `print`)
- `heteroscedastic_regression.ipynb` (quoted `print` statements)

**NumPy 2** (ndarray is no longer a Python float):

- `Integral_kernel.ipynb` — `"%0.2f" % speed`
- `Poisson regression tutorial.ipynb` — `float(rates[r])`

**Matplotlib:**

- `heteroscedastic_regression.ipynb` — `pb.errorbar(..., fmt=None)` must be
  `fmt="none"` (or another format string).

**Not Python:**

- `config.ipynb` — `defaults.cfg` / `installation.cfg` INI in **code** cells.
  Move those samples to markdown (or a raw cell).

**Kernel metadata (every tutorial notebook):**

- `kernelspec` still says `python2`. Set to `python3`.

### Design choices

1. **Mechanical port first.** Do not rewrite the teaching narrative in the
   same pass.
2. **Clear outputs** after a successful execute so git diffs stay about source
   cells, not huge Plotly blobs.
3. **`climin` notebooks** (`SVI.ipynb`, `optimizer-implementation.ipynb`):
   make the import fail clearly (short markdown + an early cell that states
   the extra). Do not add climin as a hard dependency of GPy. Skip policy is
   CIP-0003.
4. Plotly `change_plotting_library('plotly')` stays CIP-0002. After this CIP
   those notebooks may still fail on Plotly until 0002 (and a GPy backend
   fix) land.

## Implementation Plan

1. Python 3 pass: `print` / `xrange` / string literals; kernelspec `python3`.
2. NumPy 2 pass: Integral kernel and Poisson tutorial — use `.item()` (or
   `float(np.asarray(x).reshape(-1)[0])`).
3. Matplotlib: heteroscedastic `fmt="none"`.
4. `config.ipynb`: INI samples → markdown.
5. Guard `import climin` with a readable error in SVI and optimizer notebooks.
6. Execute with CIP-0003 against GPy 1.15.0; clear outputs; open the PR on
   this repository.

## Backward Compatibility

Python 2 readers cannot run the updated notebooks. GPy 1.15 already requires
Python ≥ 3.9. Markdown rendering on GitHub / nbviewer is unchanged.

## Testing Strategy

CIP-0003: `nbclient` over `GPy/*.ipynb` against GPy 1.15.0. This CIP is done
when every tutorial is valid Python 3 (syntax and kernelspec) and the
non-Plotly notebooks that failed only on `print` / `xrange` / NumPy / matplotlib
/ config complete without traceback.
