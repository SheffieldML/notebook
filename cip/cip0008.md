## Summary

Point notebook CI / tutorial installs at lamd’s shared package catalog
(CIP-001C). Keep only profiles, pins, and temporary overrides in this repo’s
`installs.yml`.

## Motivation

Package default sources (especially pods → ods) change when libraries release.
Duplicating specs in this repo and in lamd macros forces multi-repo edits.
Central catalog + local overrides matches the lamd `\installcode` model.

## Detailed Description

- `installs.yml` declares `catalog.url`, optional `catalog.local`,
  `overrides.packages`, and profiles with a package *name list* plus `pins`.
- `scripts/install_from_yaml.py` resolves:
  `pins` > `overrides` > catalog > bare name.
- Offline: `LAMD_PACKAGES_YML` / `LAMD_PACKAGES_JSON` or `catalog.local`.
- Until ods CIP-0005 is on the shared catalog / PyPI, `overrides.packages.pods`
  keeps the CIP branch.

## Implementation Plan

1. Reshape `installs.yml` to catalog + overrides + profiles
2. Update `install_from_yaml.py` to fetch/merge catalog
3. Dry-run both CI profiles
4. Keep GPy tutorials workflow pointing at the installer

## Backward Compatibility

Legacy profiles that still embed a full `packages:` mapping (name→spec) continue
to work without catalog lookup.

## Testing Strategy

- `--dry-run` for `gpy-tutorials` and `gpy-tutorials-latest`
- CI execute jobs on this branch
