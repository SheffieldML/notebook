# CIP-0006: Install GPy from the tutorial notebooks when it is missing

## Summary

Each executable GPy tutorial gets a first code cell that imports GPy if it is
already present, and otherwise installs `gpy[plotting]>=1.15.0` (the floor
these tutorials target) then imports it. Colab is the main case: CIP-0004
badges open a notebook in an empty runtime.

## Motivation

Open-in-Colab badges land on a machine with NumPy and Matplotlib, not GPy.
The first `import GPy` fails unless the reader knows to `%pip install gpy`.
Local clones and CIP-0003 already have GPy, so the same cell must be a
no-op when the import works.

## Detailed Description

**Scope:** executable `GPy/*.ipynb` (every tutorial with a code cell that
imports GPy). Skip `index.ipynb` and `config.ipynb` (markdown only). Not
`lab_classes/`, `compbio/`, `GPy-phil/`.

**Canonical cell** (identical text in every in-scope notebook, first code
cell, after the Colab badge markdown):

```python
try:
    import GPy
except ImportError:
    import subprocess
    import sys
    subprocess.check_call(
        [sys.executable, "-m", "pip", "install", "-q", "gpy[plotting]>=1.15.0"]
    )
    import GPy
```

Rationale:

- **Check then install**, not an unconditional `%pip`. CIP-0003 already
  installed GPy; a always-on pip would hit the network on every notebook.
- **`subprocess` + `sys.executable`**, not `%pip`, so nbclient and Colab
  both run it. `%pip` is Colab-friendly but is a Jupyter magic.
- **`gpy[plotting]>=1.15.0`**: tutorials need the 1.15 matplotlib path;
  Colab should get current PyPI, not be stuck on 1.14.2. Do not pin `==`
  in the notebook (that fights CIP-0003's `execute-latest` canary).
- **Do not upgrade** an already-importable GPy. A local 1.14.2 editable
  install must keep working for library development; only a missing
  module triggers pip.
- **Do not detect Colab only.** Missing GPy in any Jupyter session gets
  the same install. If import fails for a reason other than a missing
  package, the `ImportError` still surfaces after pip (second `import GPy`).

Place this cell **before** other imports that assume GPy (`GPy.plotting`,
climin guards, `import pylab` / `pyplot`). Existing `import GPy` lines in
later cells can stay (re-import is cheap) or be dropped if they become
redundant; prefer leaving them so a reader who runs a mid-notebook cell
still has `GPy` in that cell's story.

**Per-notebook extras** (same try/install pattern, only where that notebook
already depends on them):

| Extra | Notebooks |
|-------|-----------|
| `pods` | `GPyCrashCourse.ipynb`, `multiple outputs.ipynb` (and any other `import pods`) |
| `seaborn` | `sampling_hmc.ipynb` |
| `ipywidgets` | `heteroscedastic_regression.ipynb` |
| `climin` | keep the existing ImportError skip in `SVI.ipynb` and `optimizer-implementation.ipynb`; do **not** auto-install climin (optional extra, Python 3.11 `imp` constraint). Colab on 3.12 would install a package that cannot import. |

East Timor in `GPyCrashCourse` stays on `datasets_mirror` (CIP-0003). Do not
wait for a pods release for that file.

**GPy folder vs `import GPy`:** the CIP-0003 runner uses the notebook
directory as cwd so the `GPy/` tutorial folder does not shadow the library.
This bootstrap cell does not change that. Colab downloads a single file, so
there is no shadowing there.

## Implementation Plan

1. Insert the canonical cell as the first code cell in each in-scope
   notebook (or prepend it to the existing first code cell if that cell is
   only imports).
2. Add the extra try/install lines only in notebooks that import those
   packages, in the same cell or the cell that first needs them.
3. Leave `index.ipynb` and `config.ipynb` without a pip cell.
4. Run CIP-0003: every notebook must still pass with GPy already present
   (the `except` branch must not run in CI). Optionally execute one
   notebook in a venv without GPy to confirm the install branch.

## Backward Compatibility

Readers with GPy installed see one extra successful import. Readers without
GPy need network access on first run (Colab has it). The cell writes into
the current Python environment; that is the point of the Colab path.

## Testing Strategy

- CIP-0003 `execute` and `execute-latest` stay green (import-hit path).
- A throwaway venv without GPy: run one short notebook (`config` has no
  code; use `basic_kernels.ipynb` or `index` skip) and confirm pip then
  `import GPy` succeeds.
- Colab: open one badge after merge, run the first cell, confirm GPy
  installs and the next cell imports.
