# CIP-0005: Replace pylab in GPy tutorials with matplotlib.pyplot

## Summary

Stop using Matplotlib's deprecated `pylab` interface in `GPy/*.ipynb`. Import
`matplotlib.pyplot as plt` (and `numpy as np` where needed), delete
`%pylab inline` (do **not** replace it with `%matplotlib inline`), and
qualify names that today come from `from pylab import *`. Also delete
existing `%matplotlib inline` magics: Jupyter and Colab show figures
without that line.

## Motivation

GPy 1.15.0 already moved the **library** plotting path from `pylab` to
`pyplot`. Four tutorials still teach the old notebook style:

| Notebook | Current pylab use |
|----------|-------------------|
| `Poisson regression tutorial.ipynb` | `%pylab inline`, `import pylab as pb`, mixed `pb.*` / `plt.ylim` |
| `heteroscedastic_regression.ipynb` | `import pylab as pb`, `%pylab inline`, mixed `pb.*` / `plt.subplots` |
| `coregionalized_regression_tutorial.ipynb` | `%pylab inline`, `import pylab as pb`, `pylab.ion()` |
| `sampling_hmc.ipynb` | `from pylab import *`, then bare `cos`, `plot`, … |

`pylab` combines NumPy and pyplot into one namespace. Matplotlib has
discouraged that for years; `%pylab` is an IPython compatibility shim. The
other GPy tutorials already use `matplotlib.pyplot as plt`.

## Detailed Description

**Scope:** `GPy/*.ipynb` in this repository. Not `lab_classes/`, `compbio/`,
`GPy-phil/`, and not the GPy library (that change shipped in 1.15.0).

**House style:**

```python
import numpy as np
from matplotlib import pyplot as plt
```

No IPython matplotlib magics. Current Jupyter and Colab display figures
without `%matplotlib inline`; `%pylab inline` is the old combined import.

Replacements:

1. Delete `%pylab inline`. Do not write `%matplotlib inline` in its place.
2. Delete existing `%matplotlib inline` in `GPy/*.ipynb` (most tutorials still have it).
3. `import pylab as pb` / `import pylab` → `from matplotlib import pyplot as plt` (or `import matplotlib.pyplot as plt`). Rename `pb.` to `plt.`.
4. `pylab.ion()` → drop.
5. `from pylab import *` in `sampling_hmc.ipynb` → explicit `np` / `plt` names (`np.cos`, `plt.plot`, …). Do not leave a `pb` alias; the rest of the tree uses `plt`.
6. Keep GPy's own plotting API (`GPy.plotting.change_plotting_library('matplotlib')`, `GPy.plotting.show`, `plotting_library().figure`) as it is. That is not `pylab`. Rewriting those calls to raw `plt.subplots` is out of scope.

After the edits, `GPy/` must not contain `pylab`, `%pylab`, `from pylab`, or
`%matplotlib`.

## Implementation Plan

1. Edit the four pylab notebooks; grep `GPy/` for `pylab`.
2. Strip `%matplotlib inline` from every `GPy/*.ipynb` that still has it.
3. In `sampling_hmc.ipynb`, convert star-imported names to `np` / `plt`.
4. Run CIP-0003 (`scripts/run_gpy_tutorials.sh`) on the pylab four, then the full `GPy/` set.

## Backward Compatibility

Readers still see the same figures. Cells that relied on `%pylab` injecting
`array` / `linspace` into the notebook namespace will need `np.` prefixes
where they do not already import NumPy (they do, except via the pylab star
import in `sampling_hmc.ipynb`).
